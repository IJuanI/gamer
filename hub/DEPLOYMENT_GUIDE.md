# API Deployment Guide

Complete guide to deploying the GamER Hub API from development to production.

## Overview

The deployment pipeline uses:
- **GitHub Actions** for CI/CD automation
- **Google Cloud Run** for serverless API hosting
- **Firestore** for database (free tier)
- **Google Container Registry** for Docker images

This achieves **zero monthly cost** while maintaining production-grade reliability.

## Prerequisites

1. **GCP Project** (`unity-dummy`)
   - Billing enabled
   - Cloud Run API enabled
   - Container Registry enabled

2. **Git Repository** (https://github.com/gamedevs/gamer)
   - Admin access to add secrets
   - GitHub Actions enabled

3. **Local Tools**
   - `gcloud` CLI installed
   - `terraform` >= 1.0
   - Git

## Architecture

### Deployment Flow

```
Developer Push
    ↓
GitHub Actions Triggered
    ├─ Checkout code
    ├─ Build Docker image
    ├─ Push to Google Container Registry
    ├─ Deploy to Cloud Run
    │  ├─ PR: Create ephemeral revision (pr-###), 0% traffic
    │  └─ Main: Deploy to prod, 100% traffic
    └─ Post results (comment on PR, etc.)
```

### Data Flow

```
Frontend (Cloudflare Workers)
    ↓
Cloud Run API (gamer-hub-api)
    ↓
Firestore Database
    ├─ users collection
    ├─ accounts collection
    ├─ games, teams, etc.
    └─ Free tier: 1GB storage, 50k reads/day, 20k writes/day
```

## Initial Setup (One-Time)

### Step 1: Deploy Infrastructure with Terraform

```bash
cd infrastructure/terraform

# Review the deployment plan
terraform plan

# Deploy (creates Cloud Run service, Firestore, service accounts)
terraform apply
```

**What gets created:**
- Cloud Run service: `gamer-hub-api`
- Firestore database: `gamer-hub`
- Service account: `gamer-hub-api@unity-dummy.iam.gserviceaccount.com`
- IAM roles for deployment permissions

### Step 2: Create Service Account Key for GitHub Actions

```bash
cd scripts
chmod +x setup-github-actions.sh
./setup-github-actions.sh
```

This script will:
1. Create a service account key
2. Encode it to base64
3. Show instructions for adding to GitHub

### Step 3: Configure GitHub Secrets

In your GitHub repository (Settings → Secrets and variables → Actions):

**Required Secrets:**

| Secret | Value | Example |
|--------|-------|---------|
| `GCP_SERVICE_ACCOUNT_KEY` | Base64-encoded service account key JSON | (generated by script) |
| `GCP_PROJECT` | GCP Project ID | `unity-dummy` |

**Optional Secrets** (if using OAuth):

| Secret | Value |
|--------|-------|
| `DISCORD_CLIENT_ID` | From Discord Developer Portal |
| `DISCORD_CLIENT_SECRET` | From Discord Developer Portal |
| `GOOGLE_CLIENT_ID` | From Google Cloud Console |
| `GOOGLE_CLIENT_SECRET` | From Google Cloud Console |
| `JWT_SECRET` | Generate: `openssl rand -base64 32` |
| `WEB_ORIGIN` | Comma-separated CORS origins |

### Step 4: Verify Setup

```bash
# Check Cloud Run service
gcloud run services describe gamer-hub-api --region=us-central1

# Check service account
gcloud iam service-accounts describe \
  gamer-hub-api@unity-dummy.iam.gserviceaccount.com

# List service account keys
gcloud iam service-accounts keys list \
  --iam-account=gamer-hub-api@unity-dummy.iam.gserviceaccount.com
```

## Development Workflow

### Making Changes

1. Create feature branch from `main`
2. Make changes to `apps/api/`
3. Commit and push to GitHub
4. Create Pull Request

### Automatic Actions

When you push to a PR:

1. GitHub Actions automatically builds Docker image
2. Tags image as `pr-###` (e.g., `pr-42`)
3. Deploys to Cloud Run as ephemeral revision (no traffic)
4. Posts comment on PR with ephemeral API URL
5. You can test the PR version in isolation

### Testing PR Deployments

```javascript
// In browser console on any frontend page:

// Switch to PR #42 API
ephemeralApi(42)

// Switch back to production
ephemeralApi()
```

When you do this, the frontend will start using the PR version of the API for all requests. Useful for:
- Testing new API endpoints
- Verifying OAuth flow changes
- Testing database schema changes
- Performance testing

### Merging to Production

1. All PR checks must pass
2. Request code review
3. Merge to `main` branch
4. GitHub Actions automatically:
   - Builds Docker image with `latest` tag
   - Deploys to Cloud Run with 100% traffic
   - Cleans up old revisions (keeps last few)

## Monitoring & Troubleshooting

### View Deployment Status

```bash
# Watch GitHub Actions
gh run list --repo=gamedevs/gamer --limit=5

# Check Cloud Run service status
gcloud run services describe gamer-hub-api --region=us-central1

# View recent deployments
gcloud run revisions list --service=gamer-hub-api --region=us-central1 --limit=10

# View service logs
gcloud run logs read gamer-hub-api --region=us-central1 --limit=50

# Live tail logs
gcloud alpha run logs tail gamer-hub-api --region=us-central1
```

### Common Issues

#### "Image not found" Error

**Problem:** Cloud Run says image doesn't exist in Container Registry

**Solution:**
```bash
# Verify image was pushed
gcloud container images list --project=unity-dummy | grep gamer-hub-api

# If missing, check GitHub Actions logs for build failures
gh run view [RUN_ID] --repo=gamedevs/gamer
```

#### Service Deployment Fails

**Problem:** Cloud Run service won't transition to Ready state

**Check:**
```bash
# View service status
gcloud run services describe gamer-hub-api --region=us-central1

# View error conditions
gcloud run revisions describe gamer-hub-api-00001-xyz \
  --service=gamer-hub-api \
  --region=us-central1 \
  --format=json | jq '.status.conditions'
```

#### Firestore Quota Issues

**Problem:** Getting 429 errors or quota exceeded messages

**Solution:**
```bash
# Check quota usage
gcloud firestore usage --project=unity-dummy

# Monitor free tier limits
# Storage: 1GB (currently: ~)
# Reads: 50k/day (currently: ~)
# Writes: 20k/day (currently: ~)
```

### Debug Ephemeral API Switching

If `ephemeralApi()` doesn't work:

```javascript
// Check available revisions
fetch('/api/dev/switch-revision', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({revisionTag: 'pr-42'})
})
.then(r => r.json())
.then(console.log)
```

## Cost Monitoring

### Free Tier Resources

| Service | Free Tier | Actual Use |
|---------|-----------|-----------|
| Cloud Run | 2M requests/month | ~10k/month |
| Firestore | 1GB storage + 50k reads + 20k writes/day | < 5% usage |
| Container Registry | $0.10/GB/month storage | ~1GB (~$0.10) |
| Cloud Logging | 50GB/month | ~5GB |

**Total Monthly Cost: ~$0.10** (Container Registry storage only)

### Monitor Spending

```bash
# View current month's costs
gcloud billing accounts describe [ACCOUNT_ID] --format=json

# Set up budget alerts
gcloud billing budgets create \
  --billing-account=[ACCOUNT_ID] \
  --display-name="GamER Hub API" \
  --budget-amount=5 \
  --threshold-rule=percent=50
```

## Rollback Procedure

### Quick Rollback

```bash
# Switch traffic to previous revision
gcloud run services update-traffic gamer-hub-api \
  --to-revisions=[PREVIOUS_REVISION]=100 \
  --region=us-central1
```

### Rollback from Browser Console

```javascript
// Find previous working revision and switch to it
ephemeralApi('prod-v2')  // or whatever tag was used
```

## Security Best Practices

1. **Never commit secrets** to the repository
2. **Rotate service account keys** every 90 days
3. **Use GitHub secrets** for all sensitive values
4. **Enable Cloud Audit Logs** for all API activity
5. **Restrict IAM roles** to minimum required permissions
6. **Monitor for unusual activity** in Cloud Logging
